# 推しコミリマインダー

Web漫画の更新日をメールで受け取れる通知機能と、自身の購読リストをWeb上で公開・共有できる機能を備えたサービスです。

## サービス概要

散在するWeb漫画の更新情報をメールに集約する通知機能と、自身の「購読リスト」をWeb上で公開・共有できる機能を備えたリマインド＆布教ができるWebアプリです。

---

## 開発のきっかけ

自身が複数のWebマンガを追う中で感じた「更新日の失念による読み逃しの落胆」をなくしたいという思いから開発しました。
単なる個人用のリマインダーにとどまらず、ファン同士で連載を追いかける熱量を「推しコミリスト」として共有・布教できるサービスを目指しています。

---

## 解決したい課題

### ターゲットユーザー
複数のWebマンガアプリや公式サイトで連載作品を平行して読んでいるユーザー。

### 課題と既存サービスの限界
- **更新日の失念**: 各アプリの更新日がバラバラで、無料公開期間（1週間など）を逃してしまう。
- **巡回の手間**: 更新確認のために複数のアプリやブラウザを開き直すのが煩わしい。
- **既存の限界**: マンガアプリの通知は宣伝が多くピンポイントの更新が届かない。ToDoアプリでは「作品の共有・布教」ができない。

### このアプリが提供する価値（差別化ポイント）
- **メールによる一括通知**: 登録した作品の更新日に自動でメールが届き、読み逃しや無駄な巡回を防止。
- **「推しコミリスト」の共有**: リマインダー登録をそのまま「購読リストの公開・布教」へと繋げ、ファン同士でリアルタイムの連載を追う楽しさを共有。

## 7. このアプリで実現すること
### MVPで作る機能
- LINEログインによるユーザー管理: ログイン時に通知用のLINE内部ユーザーIDを取得・保持します。
- 漫画タイトル、更新周期の登録・編集・削除機能
- リマインダー登録時の利便性を高めるため、楽天ブックス書籍検索APIによるマンガタイトルの自動入力を実装します。なお、検索でヒットしない作品がある可能性を考慮し、自由入力機能も併設します。
- LINEプッシュ通知機能: 設定された更新日に基づき、自動でLINEメッセージを送信します。
- 非同期処理・自動リトライ: 送信失敗時に備え、Sidekiqを用いた通知の仕組みを構築します。
- 推しコミリストの公開機能: 自分がリマインド登録している作品を「推しコミリスト」として、Webアプリ上で公開できます。イメージは、リマインダーリスト一覧ページで「推しコミリストを作成する」ボタンを押すと、作品名が自動で入力された推しコミリストが作成されます。
作品ごとにコメントを添えられて、推しコミリストにタイトルをつけて公開できます。リストを見た人が思わず読みたくなるような布教の場を提供します。
推しコミリストは公開/非公開が選択可能です。

### ユーザーが入力する情報
- LINEログインの Scopes（スコープ） を利用して、ユーザーの同意を得た上で以下の情報を取得します。
  - openid
  - profile
    - ユーザーID: ユーザーIDを利用してメッセージを送信する
    - 表示名 / プロフィール画像: アプリ内での表示用
- ユーザーがリマインダーに入力できる情報
  - 作品名（必須）
  - 通知日時（必須）
  - 作品URLなど（任意）
- ユーザーが推しコミリストに入力できる情報
  - リストのタイトル（必須）
  - 作品名（必須）: リマインダーから引用
  - 一言コメント（任意）
  - 画像（任意）
  - URL（任意）

### 本リリースで作る機能
- LIFF (LINE Front-end Framework)の実装: LINEアプリ内から設定画面をシームレスに開けるようにします。

## 8. このアプリの懸念点とその対策
### 懸念点①
- **何が問題になりそうか**: 漫画の連載終了や休載、更新日の変更に自動で対応できない。
- **なぜそう思うか**: ユーザーが自分で情報を更新し続けるのは面倒だから。
- **そのために考えている対策**: LINE通知内に「設定を変更する」ボタンを設置し、通知を受け取ったついでに変更できる導線を作る。

### 懸念点②
- **何が問題になりそうか**: リスト作成から年数が経つと連載が終了している作品が出てくる。
- **なぜそう思うか**: リアルタイムで連載を追っている漫画を共有できることを重視しているため。
- **そのために考えている対策**: 
  - リストの作成日から判別してリストの年別カテゴリーを設けることで、「今連載されている作品なのか」を一目で分かるようにする。
  - リストに「作成日」を記載することで、「古い情報かもしれない」という前提でリストを見てもらえるため、連載終了が混ざっていてもネガティブな印象を与えにくい。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

バックエンド: Ruby on Rails 7 (ERB / Tailwind CSS)

データベース: PostgreSQL / Redis (Sidekiq用)

非同期処理: Sidekiq / ActiveJob

定期実行: whenever (cron)

ログイン: LINE Messaging API (LINEログイン) / Devise / OmniAuth

プッシュ通知: LINE Messaging API (Push Message) / line-bot-sdk-ruby

マンガタイトルの自動入力: 楽天ブックス書籍検索API / rakuten_web_service
